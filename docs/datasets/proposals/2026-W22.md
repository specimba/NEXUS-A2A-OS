## Proposal 1: CDR-Stage Transition Traces
- **Source**: Synthetic — generated from the CDRStage state machine in `trust_engine_v2.py` using parameterized Markov walks across the 6 CDR stages
- **Schema**:
  ```
  trace_id:        string   UUID of the session trace
  timestamp:       float    Unix timestamp of transition
  from_stage:      string   CDRStage enum value (NORMAL|DEGRADED_REASONING|…)
  to_stage:        string   CDRStage enum value after transition
  trust_score:     float    Trust score at time of transition (0–100)
  regression_events: int    Count of regression events in prior window
  entropy_estimate: float  Output entropy proxy (e.g. log-perplexity from model response)
  tokens_consumed: int      Tokens spent in this stage
  was_hard_block:  bool     Whether this transition triggered the CRITICAL hard block
  ```
- **Why NEXUS cares**: `trust_engine_v2.py` implements a 6-stage CDR state machine with hard escalation thresholds — but there is no dataset of real state transitions to tune the escalation sensitivity. This dataset would enable calibrating `should_escalate()` thresholds per stage instead of the current hardcoded constants.
- **Estimated effort**: M (12–20 h) — synthetic generation via parameterized simulation script; Markov walk can be tuned to match observed trust score distributions.
- **First slice**: 1,000 traces covering NORMAL→DEGRADED_REASONING and DEGRADED_REASONING→MEMORY_CORRUPTION transitions only, with uniform trust scores for rapid iteration.

## Proposal 2: Intent-Routing Failure Modes
- **Source**: Synthetic — generated by sampling `IntentClassifier.KEYWORDS` patterns from `dynamic_router.py` and perturbing them to produce misclassifications
- **Schema**:
  ```
  sample_id:        string   UUID
  prompt_text:     string   Input prompt (synthetic)
  true_intent:     string   Injected ground-truth intent
  predicted_intent: string  IntentClassifier.classify() output
  confidence:      float    Max keyword match score (0–1)
  strategy_used:   string   RoutingStrategy used (quota_aware|cost_optimized|…)
  model_selected:  string   model_id from ModelsRegistry that was selected
  fallback_chain:  list     Fallback model_ids actually invoked
  fallback_used:   bool     Whether a fallback was triggered
  latency_ms:      int      End-to-end observed latency
  cost_estimate:   float    Cost estimate from RouteResult
  intent_was_correct: bool  Whether true_intent == predicted_intent
  ```
- **Why NEXUS cares**: `dynamic_router.py` routes prompts by intent — misclassifications (e.g. CODE↔REASONING) cause wrong model selection and unnecessary fallback chain invocation, inflating latency and cost. There is no dataset of misclassification patterns to improve `IntentClassifier` keyword sets or add a lightweight embedding layer.
- **Estimated effort**: M (15–25 h) — requires generating a prompt corpus with known intent labels and running `IntentClassifier.classify()` in a loop; perturbation logic handles the misclassification injection.
- **First slice**: 500 synthetic prompts biased toward CODE/REASONING boundary cases (e.g. "debug this logic error" vs "explain this reasoning").

## Proposal 3: Memory-Adversarial Write Patterns
- **Source**: Synthetic — generated by simulating adversarial writes to the S-P-E-W memory hierarchy based on the layer constraints defined in `memory_adapter.py`
- **Schema**:
  ```
  write_id:         string   UUID
  agent_id:         string   Simulated agent identifier
  layer:            string   S-P-E-W layer targeted (session|project|experience|wisdom)
  content:          string   Synthetic memory write content
  is_adversarial:   bool     Whether this write was generated by an adversarial policy
  write_velocity:   float   Writes-per-minute from poisoning.py WriteRecord
  tfidf_contradiction_score: float  Cosine similarity from _TfidfIndex (adversarial vs prior writes)
  pattern_anomaly_score: float  Z-score on write-size distribution per agent_id
  poisoning_flagged: bool    Output of poisoning.py MINJA detector
  poisoning_stage:   int     MINJA layer that triggered flag (1|2|3|0 if not flagged)
  mem0_available:   bool    Whether mem0 cloud was available (determines fallback path)
  ttl_assigned:      int     Assigned TTL in seconds (None for experience/wisdom)
  ```
- **Why NEXUS cares**: `poisoning.py` uses a 3-layer detector (write velocity + TF-IDF contradiction + statistical anomaly) but has no benchmark dataset of known adversarial vs benign writes to measure precision/recall per layer. A labelled dataset would allow tuning the Z-score thresholds per layer and evaluating whether TF-IDF layer actually adds value over velocity alone.
- **Estimated effort**: S (8–14 h) — the poisoning detector and TF-IDF index already exist; generating adversarial writes requires writing a policy that produces contradiction patterns while staying below velocity thresholds.
- **First slice**: 2,000 writes (80% benign, 20% adversarial) covering session and project layers only, with ground-truth poisoning_flagged labels.

## Trade-offs to flag for speci
- **CDR-Stage Traces**: The agent has no authority to decide whether to use real production traces (vs synthetic) for threshold calibration — that decision belongs to the trust_engine_v2 owner. Mark as blocked pending that decision.
- **Intent-Routing**: The KEYWORDS map in `IntentClassifier` is hand-maintained; improving it with a labelled dataset could justify adding a lightweight embedding model. No decision yet on whether to use open-source embeddings (e.g. sentence-transformers) or keep it keyword-only.
- **Memory-Adversarial**: The TF-IDF layer in `poisoning.py` uses a stdlib-only implementation; a labelled dataset would reveal whether the current TF-IDF similarity threshold (implicit in `_TfidfIndex`) is correctly tuned or needs replacement with a proper embedding model.
