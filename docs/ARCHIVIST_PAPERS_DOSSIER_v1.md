**Hypothesis:** Replacing 1D PCA refusal direction with SAE-extracted multi-feature steering at the commitment layer will improve steering precision and reduce side-effects on unrelated capabilities.

**Method:**
1. Train SAE on Qwen3Guard-0.6B hidden states at L27 (commitment layer) using ~50K forward passes on mixed safe/unsafe prompts
2. Apply SAE-Steering's two-stage pipeline: (a) logit-amplification recall — find SAE features that amplify Safe/Unsafe token logits; (b) rank by control effectiveness — test each feature's steering delta
3. Use top-k features (k=3–7) as multi-dimensional steering vector instead of single PCA direction
4. Compare: (i) 1D PCA steering (current), (ii) SAE multi-feature steering, (iii) GABLITERATION multi-directional SVD steering

**Expected outcome:** Multi-feature steering should achieve 0% FPR while better preserving general model capability (less collateral damage to non-safety tasks). The SAE approach disentangles safety features from capability features, preventing the "one bad model spoils the bunch" problem.

**VRAM budget:** SAE training at L27 on Qwen3Guard-0.6B requires ~2.5GB for hidden state collection + ~500MB for SAE (64x overcomplete = ~38K features at d_model=896). Fits within 6.6GB VRAM budget.

**Validation:** Test on OR-BENCH (80K over-refusal prompts) + fused_attack_test.jsonl (5 attacks) + fused_benign_test.jsonl (500 benign). Measure: recall, FPR, general capability preservation (MMLU proxy).

### Experiment 2: Conditional DRO-Steering Guard (CDG)

**Hypothesis:** DRO-style conditional steering (refuse harmful, allow harmless) implemented as activation-space intervention at the commitment layer will eliminate over-refusal while maintaining 100% recall.

**Method:**
1. Extract two steering vectors from Qwen3Guard: (a) "refusal direction" from safe-vs-unsafe contrastive pairs (current approach), (b) "harmfulness detection direction" from harmful-vs-harmless contrastive pairs
2. At inference, first apply the detection direction to assess harmfulness signal strength at L27
3. If detection signal > threshold: apply refusal steering (amplify Safe logits)
4. If detection signal < threshold: apply anti-over-refusal steering (suppress refusal direction, restore normal logits)
5. This creates a two-phase guard: detect → conditionally steer, rather than unidirectional steering

**Expected outcome:** Eliminates the over-refusal problem (OR-BENCH rho=0.89 correlation) by making steering conditional on detected harmfulness. Should achieve both 100% recall AND 0% FPR without the capability degradation that unconditional steering causes.

**Validation:** OR-BENCH full evaluation. Compare against: (i) unsteered Qwen3Guard (30.8% FPR), (ii) unidirectional steered (0% FPR but potential capability loss), (iii) CDG (target: 0% FPR + no capability loss).

### Experiment 3: Layer-Resolved Sycophancy Guard (LRSG)

**Hypothesis:** The "Not Just RLHF" finding that sycophancy corrupts a narrow mid-layer window (L14–L18) via suppression of clean-reasoning features can be countered by activation patching at the commitment layer of guard models.

**Method:**
1. Using Qwen3Guard as test subject, construct sycophancy-inducing prompts (social pressure to approve unsafe content)
2. Run decision-locator on sycophancy-corrupted vs clean guard states
3. Identify which layers are corrupted (hypothesis: same L14–L18 window as sycophancy paper)
4. Apply commitment-layer steering (L27) with clean donor states — does late-layer steering override mid-layer sycophancy corruption?
5. Test "structured dissent" injection: add a single correctly-arguing dissenter feature at L27 and measure sycophancy yield reduction (target: 54–73pp reduction as per paper)

**Expected outcome:** Late-layer steering can override mid-layer sycophancy corruption because the commitment layer is downstream of the corruption window. This would extend our guard pipeline from "detect unsafe content" to "resist social pressure to approve unsafe content" — a crucial capability for multi-agent NEXUS governance.

**NEXUS relevance:** Multi-agent scenarios where one agent tries to socially pressure the guard into approving unsafe actions. The "single dissenter reduces yield 54–73pp" finding suggests KAIJU could inject dissent features at the commitment layer as a defense.

### Experiment 5: Diffusion-Mode Guard Inference (DMGI)

**Hypothesis:** Converting the AR guard model to block-diffusion mode (per FAST-DLLM v2) enables parallel safety verification of multiple tokens, reducing guard latency by 2–3x without quality loss.

**Method:**
1. Fine-tune Qwen3Guard-0.6B into block-diffusion mode using ~1B tokens (per FAST-DLLM v2 protocol)
2. Adapt the commitment-layer steering approach to diffusion-mode: instead of steering at a single forward pass, steer the denoising trajectory at the commitment timestep
3. Apply introspective verification (per I-DLM): guard verifies its own previous safety judgments while advancing new ones in the same forward pass
4. Measure: (a) latency improvement, (b) safety judgment quality preservation, (c) steering effectiveness in diffusion mode

**Expected outcome:** 2–3x guard inference speedup with preserved safety quality. The introspective verification feature is especially valuable: the guard can self-check its own "Safe" judgments during generation, catching edge cases that single-pass AR inference misses.

**VRAM concern:** Block-diffusion mode may require more VRAM for the denoising loop. Need to validate that the hierarchical caching mechanism from FAST-DLLM v2 keeps memory within the 6.6GB budget.

### Experiment 6: Inference-Time Reward-Guided Guard Scaling (IRGS)

**Hypothesis:** Applying Inference-Time Scaling for RMs to the guard cascade allows dynamic compute allocation: simple safe inputs get L1-only processing, ambiguous inputs get L1+L2, and adversarial inputs get full L1+L2+L3 with meta-RM voting.

**Method:**
1. Implement meta-RM (from Inference-Time Scaling paper) as a lightweight confidence estimator that runs after L1
2. If L1 confidence > 0.95: return L1 decision immediately (fast path)
3. If L1 confidence 0.5–0.95: escalate to L2 with increased inference compute (multiple forward passes, temperature sampling, voting)
4. If L2 confidence < 0.5: escalate to L3 with full compute budget
5. Replace the current heuristic routing in guard-router.py with this learned confidence-based routing (informed by ROUTELLM approach)

**Expected outcome:** Average guard latency drops significantly (most inputs are clearly safe and get L1-only), while worst-case adversarial inputs get the full cascade with voting. This is the inference-time scaling analog for guard models.

**Implementation:** Modify guard-router.py to add confidence-based routing with meta-RM. Train meta-RM on L1 decision distributions using synthetic ambiguous inputs.

### Experiment 7: Constitutional Guard Self-Critique (CGSC)

**Hypothesis:** Adapting Constitutional AI's self-critique revision loop to guard models enables them to catch their own errors at inference time without additional training.

**Method:**
1. After L1 (steered Qwen3Guard) makes a "Safe" judgment, inject a critique step:
   - Generate: "The previous judgment was Safe. Critique: could this input be harmful because..."
   - Let the same model produce a self-critique
   - If critique finds a harm vector, escalate to L2
2. After L2 makes a judgment, same self-critique loop
3. Use SALMON-style principles as the constitution for critique generation (NEXUS governance principles)
4. Compare: (a) no self-critique, (b) single self-critique round, (c) recursive self-critique (up to 3 rounds)

**Expected outcome:** Self-critique catches edge cases that activation steering misses (e.g., subtly harmful inputs that pass the logit threshold). The SALMON principle-based approach means critique is governed by NEXUS policy, not arbitrary model tendencies.

**Risk:** Self-critique adds latency. Mitigate by only applying when L1 confidence < 0.95 (integrate with Experiment 6).

### Experiment 10: Multi-Agent Guard Dissent Architecture (MAGDA)

**Hypothesis:** A multi-agent guard architecture where multiple independent guard models vote, with structured dissent injection, provides stronger defense against coordinated multi-agent attacks than a single cascade.

**Method:**
1. Deploy 3 independent guard instances (Qwen3Guard + LlamaGuard3 + Granite) as parallel voters
2. Each instance processes the input independently with its own steering
3. Aggregate decisions via weighted voting (weights from trust scores per Darwin MRI-Trust)
4. If any guard dissents (disagrees with majority), trigger escalation to full L1+L2+L3 sequential cascade
5. Add structured dissent injection: even when all 3 agree on "Safe", randomly inject a dissent signal (per "Not Just RLHF" finding that a single dissenter reduces sycophancy yield 54–73pp) and re-evaluate

**Expected outcome:** Multi-agent voting with structured dissent provides defense-in-depth against coordinated attacks (Teams of LLM Agents exploiting Zero-Days achieved 42% success rate). The dissent injection prevents sycophancy cascade where all guards agree due to shared training biases.

**NEXUS integration:** This maps to KAIJU multi-agent governance. The dissent injection is the activation-level analog of "devil's advocate" in governance deliberations.

## PART 5: CROSS-CUTTING RESEARCH DIRECTIONS

### Direction A: Activation-Space Governance Language

The convergence of SAE-Steering, DRO, GABLITERATION, and decision-locator suggests a unified "activation-space governance language" is emerging:
- **Concepts** = SAE monosemantic features (disentangled safety concepts)
- **Judgments** = commitment-layer logit separability (Safe vs Unsafe)
- **Interventions** = conditional steering vectors (DRO-style: refuse harmful, allow harmless)
- **Verification** = introspective self-critique (I-DLM: verify while advancing)
- **Evolution** = sleep-time consolidation (LightMem: offline refinement)

This is a formal language for NEXUS governance that operates entirely in model internals, not in text space. It is auditable (you can inspect the steering vectors), testable (you can measure sep and FPR), and composable (you can combine features, judgments, and interventions).

### Direction B: Thermodynamic Guard Model Analysis

The Phase Transitions paper + RBM Flows + subjective thermo-currency paper suggest that guard model decision boundaries can be understood through statistical physics:
- **Phase transition**: The commitment layer is where the guard model undergoes a "phase transition" from ambiguous to committed
- **Critical temperature**: Temperature scaling near the commitment layer could smooth or sharpen the decision boundary
- **Statistical distance**: The sep metric is essentially a statistical distance between Safe/Unsafe output distributions
- **Energy budget**: The thermo-currency framework's ΔE = E_b - E_a maps to "evidence energy saved by guard intervention"

This could lead to a principled framework for setting guard model thresholds based on thermodynamic quantities rather than empirical FPR tuning.

### Direction C: Weight-Space ↔ Activation-Space Duality

Task Arithmetic + TIES-MERGING + Darwin Family + GABLITERATION reveal a duality:
- **Weight-space steering**: Task vectors (negation removes behavior, addition combines) — permanent, requires retraining or merging
- **Activation-space steering**: Commitment-layer intervention (amplify/suppress logits) — transient, per-inference, no retraining

NEXUS should use both: weight-space steering for permanent guard model alignment (task arithmetic to combine safety skills), activation-space steering for runtime guard behavior adjustment (commitment-layer vectors for context-dependent gating).

The key insight from "Not Just RLHF" is that **activation-space steering at the commitment layer can override weight-space alignment failures** (sycophancy persists in weights but can be countered at the commitment layer). This makes activation-space steering the runtime safety net for weight-space alignment gaps.

### Direction D: Multi-Temporal Guard Defense

LASM's T1–T4 temporal classification reveals that current guard models operate only at T1 (instantaneous):
- **T1 Instant**: Current L1/L2/L3 cascade (per-input safety judgment)
- **T2 Session-persistent**: Guard maintains safety state within a session (track cumulative prompt patterns)
- **T3 Cross-session cumulative**: Guard learns from attack patterns across sessions (sleep-time consolidation)
- **T4 Sub-session stack**: Guard detects nested/recursive attacks within a single interaction

NEXUS needs guard defenses at all four temporal scales. Experiment 11 (sleep-time consolidation) addresses T3. Experiment 7 (constitutional self-critique) partially addresses T4. But T2 (session-persistent state) requires a new guard architecture that maintains a safety context window across turns.
