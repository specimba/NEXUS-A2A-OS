## Findings (NEXUS-relevant only)

### 1. Self-Healing Framework for Reliable LLM-Based Autonomous Agents
- Source: https://arxiv.org/abs/2605.06737v1
- Why NEXUS cares: The paper introduces a quantitative reliability assessment + failure detection taxonomy (hallucination, execution error, reasoning inconsistency) with adaptive replanning and corrective prompting. NEXUS's `src/nexus_os/governor/trust_engine_v2.py` (Contain→Detect→Respond) and `src/nexus_os/monitoring/token_guard.py` lack an explicit self-healing loop that ties internal reasoning state to external execution results. This taxonomy would sharpen the failure classification in the Respond stage.
- Suggested follow-up: Evaluate the failure taxonomy against existing NEXUS failure modes; consider whether `trust_engine_v2.py` should emit recovery sub-states (REPLANNING, CORRECTIVE_PROMPT, ROLLBACK) aligned with the paper's model.

### 2. OpenSkynet Terminator Mode — 7-Phase Autonomous Pipeline with Adaptive Resilience
- Source: https://github.com/sediman-agent/OpenSkynet/pull/120
- Why NEXUS cares: The PR introduces a 7-state pipeline (Verification gate → Dependency-aware orchestration → Integration → Adaptive resilience → Quality gate → TrajectoryDB → Adversarial hardening) with exponential backoff, filesystem snapshots, and red-team contract verification. NEXUS's `src/nexus_os/engine/` has a DAG executor but no explicit adaptive resilience layer (re-decomposition on >50% failure rate, checkpoint rollback). This architecture fills a gap in NEXUS's failure-recovery story.
- Suggested follow-up: Prototype a `ResilienceController` in `src/nexus_os/engine/` that mirrors the 7-phase state machine — tracking failure rate, triggering re-decomposition, and managing filesystem snapshots on degraded execution.

### 3. Edamame — Runtime Verification for AI Coding Agent Intent Drift
- Source: https://securityweek.com/new-edamame-platform-aims-to-catch-ai-coding-agents-going-off-the-rails/
- Why NEXUS cares: Edamame uses host telemetry + ML to detect when a coding agent drifts from operator intent, distinguishing "is this developer trusted?" from "did the agent stay inside intent on this host under this posture?" This maps to NEXUS's `src/nexus_os/security/sanitizer.py` (currently screens terminal output but not agent behavioral drift) and `src/nexus_os/governor/trust_kernel.py` (CDR-stage gate). Intent drift is a distinct threat from prompt injection — it is behavioral, not content-based.
- Suggested follow-up: Add an `IntentDriftMonitor` that consumes host telemetry events and emits `agent-intent-drift` to the audit pipeline; integrate with `trust_kernel.py` CDR-stage to halt or confirm agent actions on high drift scores.

### 4. ACSE — Adaptive Conformal Semantic Entropy for Hallucination Detection
- Source: https://openreview.net/forum?id=VExQ2rOzNS
- Why NEXUS cares: ACSE (Adaptive Conformal Semantic Entropy) operates at the semantic level — softly clustering model outputs by meaning dispersion, inflating uncertainty adaptively, and applying conformal calibration for distribution-free reliability guarantees. This is a stronger hallucination detector than NEXUS's current `src/nexus_os/monitoring/token_guard.py` (which tracks token consumption but not semantic consistency). Embedding ACSE would give the monitoring layer a principled early-warning signal for hallucination before output reaches the user.
- Suggested follow-up: Prototype an `SemanticEntropyMonitor` that runs in parallel with generation, scoring each output token window for semantic entropy spikes; emit `hallucination-suspicion` events to `src/nexus_os/observability/audit_log.py` when above threshold.
