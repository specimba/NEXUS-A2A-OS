### 1. MCP v2.1 Streamable HTTP — 10x Throughput, ~95% Latency Drop vs SSE; Elicitation Now a First-Class Protocol Primitive
- Source: https://agentmarketcap.ai/blog/2026/06/07/mcp-v2-1-streamable-http-95-percent-latency-reduction ; cross-confirmed https://dev.to/om_shree_0709/amazon-bedrock-agentcore-gateway-just-became-the-enterprise-mcp-infrastructure-layer-heres-what-m4o
- Why NEXUS cares: MCP v2.1 ratifies Streamable HTTP (SH) as the replacement for stateful Server-Sent Events (SSE), with measured 10x throughput uplift under realistic concurrency and ~95% P99 latency reduction for stateless round-trips. SH supports two modes: stateful (carrying an `MCP-Session-Id` header for session continuity) and fully stateless (RPC-style, friendly to round-robin load balancers and autoscaling). The v2.1 spec also elevates *elicitation* — human-in-the-loop as a protocol primitive — and standardizes OAuth 2.1 OBO token exchange. For NEXUS this lands in three places. First, `src/nexus_os/mcp/server.py` should audit its current transport: if it launches via stdio (the prior `2026-06-03-00` note already flagged stdio injection risk) it almost certainly needs to add an SH code path that gates stateless mode behind a feature flag. Second, `src/nexus_os/bridge/sdk.py` already wraps outbound calls with a `CircuitBreaker`; switching the underlying MCP transport from SSE to SH means the SDK can shed per-session state and the breaker can key on a 5-tuple (model, lane, agent, tool, action) instead of session-id — a much more meaningful breaker key for the OpenClaw swarm. Third, `src/nexus_os/security/sanitizer.py` must add an SH-aware header allowlist: a malformed or missing `MCP-Session-Id` is a downgrade-attack vector, and the sanitizer should reject outbound SH responses whose session id drifts from the issued id within a single turn.
- Suggested follow-up: Add an SH transport option to `src/nexus_os/mcp/server.py` keyed on a `NEXUS_MCP_TRANSPORT=streamable_http|stdio|sse` env var; default to SH for any service started in 2026 or later. Update `src/nexus_os/bridge/sdk.py`'s `CircuitBreaker` to accept an optional `breaker_key_fn` so transport-level keying can switch from session-id to a deterministic 5-tuple. Add a SH header validator to `src/nexus_os/security/sanitizer.py` that enforces `MCP-Session-Id` monotonicity per request stream and rejects cross-stream reuse. Cross-reference with the `mcpTrustVerifier` idea from `2026-05-31-00`: SH's stateless mode makes the verifier's per-request check materially cheaper.

### 2. Ajah — Async Overconfidence Detector for High-Stakes LLM Domains (hedge_risk = certainty × complexity)
- Source: https://dev.to/vignesh_reddy_53e403f62d2/the-llm-failure-mode-nobody-is-monitoring-overconfident-responses-in-high-stakes-domains-2min ; https://github.com/VigneshReddy-afk/ajah ; https://useajah.com
- Why NEXUS cares: Ajah exposes a failure mode that NEXUS's existing hallucination stack (HaluNet per `2026-06-04-12` finding #1, LongTracer per `2026-06-04-12` out-of-scope) does *not* cover: an LLM can be factually correct *and* overconfident in a high-stakes domain, and a governance layer that only flags hallucinations will let confidently-wrong medical / legal / financial advice through. Ajah's signal is text-only and runs async with zero added latency, scoring each response on two axes: (a) question complexity (presence of high-stakes domain cues, conditional language, multi-part uncertainty), (b) response certainty (use of absolute terms without hedging). The composite `hedge_risk = certainty_score × complexity_score` is a single scalar that fires when a model asserts unearned authority. NEXUS's `src/nexus_os/monitoring/trust_scorer.py` already produces a scalar trust score per inference via `LaneParams` (alpha/beta/gamma/eta/kappa), but the formula weights evidence quality and harm — it does not consume linguistic certainty or domain-stake cues. Adding an `OverconfidenceBranch` keyed on (a) NER-driven domain cue detection (a small rule set on medical/legal/financial tokens) and (b) a deterministic certainty-heuristic (count of absolute adverbs and zero hedging markers) would give the trust kernel a third orthogonal signal to combine with HaluNet's internal-signal branch and the existing evidence-quality branch — closing a gap where hallucination detectors flag *wrong* outputs but overconfidence detection flags *under-hedged right-or-wrong* outputs. Ajah is MIT-licensed and self-hosted, so the integration is purely additive code on the trust_scorer side, with no new external service.
- Suggested follow-up: Add a `compute_hedge_risk(question, response) -> float` helper to `src/nexus_os/monitoring/trust_scorer.py` using a small deterministic regex set (no model call, no LLM-as-judge) and a domain-cue list. Expose `hedge_risk` as a third component in the existing `LaneParams` weight set, defaulting to 0.15. In `src/nexus_os/governor/trust_kernel.py` (CDR-stage Detect), require `hedge_risk > 0.7` *and* `domain_stake in {medical,legal,financial}` before triggering a hold-queue entry — both must be present to avoid saturating the Kaiju hold queue with everyday low-stakes overconfidence. Add a Loki label `nexus.trust.hedge_risk` so the existing dashboards can correlate overconfidence with HaluNet's `hallucination-risk-score`.

### 3. Bedrock AgentCore Gateway — Production MCP Infrastructure with Native Elicitation and PrivateLink Egress
- Source: https://dev.to/om_shree_0709/amazon-bedrock-agentcore-gateway-just-became-the-enterprise-mcp-infrastructure-layer-heres-what-m4o (cross-confirmed by awslabs/agentcore-samples on GitHub)
- Why NEXUS cares: Amazon Bedrock AgentCore Gateway is the first managed gateway to ship first-class MCP support that also functions as a policy / observability / credential broker — it centralizes OAuth OBO token exchange, RBAC, OpenTelemetry traces, and PrivateLink-only egress for tool targets. NEXUS's `src/nexus_os/mcp/server.py` is the canonical governance MCP, but the *gateway layer* (which brokers outbound tool calls from OpenClaw agents) is currently spread across `src/nexus_os/bridge/sdk.py` and ad-hoc process services. AgentCore's design gives NEXUS a clean reference architecture for what a NEXUS-native gateway should look like: a single ingress that (a) authenticates via the existing SLACK_BOT_TOKEN / GITHUB_TOKEN style env-driven secrets, (b) enforces a `kaiju_auth.py`-style impact/intent gate per outbound tool call, (c) emits an OTel span carrying the same `nexus.monitoring.breaker` label set Loki queries already use. Two specific AgentCore features map cleanly: *elicitation* (treat human-in-the-loop as a protocol primitive) maps onto NEXUS's existing Kaiju hold-queue pattern in `src/nexus_os/governor/kaiju_auth.py` — a tool call that exceeds impact threshold can be paused, the hold-queue record is the "elicit" message, and the human's approve/deny is the response. *Dynamic target listing* (per-target opt-in at gateway creation) maps onto the FunctionGemma router in `src/nexus_os/mcp/functiongemma_router.py` — instead of statically registering every tool in `models.json`-style config, the router can query the gateway for currently-permitted tools per agent/lane, reducing the risk of an agent calling a now-revoked tool.
- Suggested follow-up: Define a thin `src/nexus_os/gateway/` package (mirroring the existing `gateway` subfolder pattern in `bridge/`) that wraps the MCP ingress with a Bearer-token auth + OTel tracing + Kaiju impact-gate, and refactor `src/nexus_os/bridge/sdk.py` to call through it. Add a `nexus.gateway.elicitation` event type to the VAP chain (`src/nexus_os/governor/proof_chain.py`) so human-in-the-loop pauses are durably auditable — this gives NEXUS a property AgentCore advertises but does not yet expose as a queryable event. Update `src/nexus_os/mcp/functiongemma_router.py` to support a "permitted tools" call that reads the active gateway's policy; cache the result for the duration of one agent turn and invalidate on impact-gate denial.
