## Findings (NEXUS-relevant only)

### 1. Adaptive Tier-Based Routing with Cascading Failover
- Source: https://github.com/kjames2001/hermes-router-proxy + https://github.com/Shubham-Jitendra-Bhadra/inference-router
- Why NEXUS cares: NEXUS's `src/nexus_os/gmr/` (GMR router) and ModelRelay at `localhost:8040` implement adaptive model selection but lack explicit circuit-breaker semantics. hermes-router-proxy demonstrates a production pattern: local flash classifier (qwen2.5:3b) classifies prompts as simple/complex, routes to cheap/fast vs. smart/expensive tiers, with a 3-tier fallback cascade (primary → fallback1 → fallback2, 502 on total failure). `inference-router` adds Complexity/Cost/Latency strategies with per-tier failover. NEXUS's `src/nexus_os/engine/gmr_router.py` should adopt an explicit failover cascade with hard latency SLAs to prevent upstream NIM timeouts from cascading into the orchestrator.
- Suggested follow-up: Add a circuit-breaker state machine to `src/nexus_os/engine/gmr_router.py` — open on consecutive failures, half-open on probe, close on success. Compare against `kjames2001/hermes-router-proxy` fallback cascade.

### 2. Two-Stage Tool Routing for Small Language Models
- Source: https://github.com/Doorman11991/smallcode (adaptive_router.js + litecode architecture v0.9.9)
- Why NEXUS cares: NEXUS's `src/nexus_os/mcp/functiongemma_router.py` routes function calls via an intent classifier. SmallCode demonstrates a concrete 2-stage pattern: (1) coarse category classification (read/write/search/run/plan) to reduce context, then (2) fine-grained tool selection within that category. Its `AdaptiveModelRouter` also monitors per-model failure rates and auto-switches models when error rate crosses thresholds. This is directly applicable to `functiongemma_router.py` — the category pre-classification stage could reduce Token Guard overhead and improve routing accuracy for the small-model case.
- Suggested follow-up: Add a coarse category pre-classification step to `src/nexus_os/mcp/functiongemma_router.py` before the fine-grained intent classification. Borrow the `AdaptiveModelRouter` failure-rate monitoring pattern for `src/nexus_os/monitoring/token_guard.py`.

### 3. Skill Trust and Lifecycle Governance for MCP
- Source: https://openreview.net/forum?id=Er0p92BsmW (Agent Skills for LLMs survey)
- Why NEXUS cares: The survey identifies that ~26% of community-contributed MCP skills have security vulnerabilities and introduces a four-tier Skill Trust and Lifecycle Governance Framework mapping skill provenance to graduated runtime permissions. NEXUS's `src/nexus_os/mcp/server.py` exposes tools via the NexusGovernanceMCP, but currently has no per-skill provenance tracking or permission tiers. This is a gap: if external skills are loaded into the MCP server, there is no trust-gated permission model. The governance framework (trust tiers → graduated capabilities) maps directly onto `src/nexus_os/governor/trust_kernel.py` and `src/nexus_os/governor/compliance.py`.
- Suggested follow-up: Design a skill provenance + tier permission model in `src/nexus_os/mcp/server.py`. Cross-reference with the four-tier framework in the Agent Skills paper. Watch only for now — requires scoped integration design.
