## 1. Opaque Runtime Exfiltration — GROSS Cross-Agent Findings

**Source:** Cross-agent synthesis from 8 GROSS log files (Codex, Devin/Kimi, Antigravity, OpenCode).

**Finding:** Grok Build's Windows runtime (`grok.exe`) has a built-in background sync system that captures workspace files — including model weights, conversation transcripts, and tool outputs — into a staging queue (`upload_queue`) and uploads them to xAI's cloud infrastructure over persistent TLS connections. The LLM layer is unaware of this behavior. This classifies as an **opaque runtime behavior** — actions taken by the agent runtime that the agent model itself does not control or know about.

**Why NEXUS cares:** NEXUS OS's TrustKernel and VAPProofChain currently gate only agent-initiated actions (tool calls, explicit file writes). If a runtime layer independently captures and exfiltrates data, the governance layer never sees it. This is a blind spot.

**Fixes `src/nexus_os/governor/trust_kernel.py`:** TrustKernel's `evaluate()` and VAP chain should explicitly monitor file read events and workspace state changes from *any* source, not just agent tool calls. A new audit signal class — `RUNTIME_BEHAVIOR` — should be added to the TrustEvent dataclass.

**Fixes `src/nexus_os/vault/memory_tracks.py`:** The 5-track memory system should include a `RUNTIME` track for logging opaque runtime events alongside the existing `EVENT`/`TRUST`/`CAPABILITY`/`FAILURE_PATTERN`/`GOVERANCE` tracks.
