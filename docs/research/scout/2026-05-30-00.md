## Findings (NEXUS-relevant only)

### 1. Protocol-Fixed Information-Theoretic Hallucination Reporting (Evidence-Weak LLM Outputs)
- Source: https://openreview.net/forum?id=GrzrPoRfEH
- Why NEXUS cares: The paper introduces information-energy metrics — sequence-level information energy, variational free energy, KL decomposition, coarse-graining-induced information loss — as a closed, auditable reporting object for evidence-weak hallucinations in LLM outputs. NEXUS's `src/nexus_os/monitoring/token_policy.py` and `src/nexus_os/monitoring/token_guard.py` track token consumption and enforce hard stops; introducing an information-energy reporting channel here would give the Token Guard a hallucination-signal dimension beyond pure consumption counts. The same metrics could feed into `src/nexus_os/governor/proof_chain.py` (VAP chain) as compositional evidence of output reliability.
- Suggested follow-up: Evaluate whether variational free energy metrics can be added as a logging side-channel to the existing token guard pipeline — lightweight tag on each output, comparable across models.

### 2. Thermodynamics of Attention — Landauer Bound as Inference-Time Feature importance Diagnostic
- Source: https://www.mdpi.com/2673-2688/7/6/194
- Why NEXUS cares: The paper treats softmax attention as an equilibrium thermodynamic system and defines a Landauer-type bound on learning: loss reduction is bounded by the entropic cost of structuring attention in the presence of noise. It introduces "thermodynamic work" as an inference-time feature importance measure that outperforms standard attention weights. Maps onto NEXUS's hallucination detection pipeline: if attention work can flag anomalous attribution patterns, it could serve as a grounding signal complementing the multi-model majority vote already noted in the prior scan. Relevant to `src/nexus_os/vault/memory_adapter.py` (trust-scored memory retrieval) where noisy attention can poison trust scores.
- Suggested follow-up: Watch only — this is pre-print/empirical. Monitor for follow-up papers that tie thermodynamic work measures to hallucination rates directly.

### 3. Resilient-LLM-Router — Separate Cooldown Circuit Breaker with Per-Failure-Type State
- Source: https://github.com/eleata/resilient-llm-router
- Why NEXUS cares: The library implements a three-state resilience model separating rate-limit, quota, and circuit-health — each with independent cooldowns rather than a single TTL. This corrects a common bug where conflating rate-limit exhaustion with quota exhaustion leads to retry storms. NEXUS's ModelRelay (`localhost:8040`) routes to deepseek-v4-flash via NVIDIA NIM and has no published circuit-breaker implementation. A separate-per-failure-type breaker at the relay layer would prevent a single exhausted API key from triggering retries that also fail, a scenario that compounds latency under load.
- Suggested follow-up: Consider adding a three-state circuit breaker to `src/nexus_os/relay/` or the ModelRelay wrapper — separate cooldowns for 429 vs. 5xx vs. quota-exhausted, with distinct open/half-open semantics per failure class.

### 4. SmallCode 2-Stage Tool Routing — Category-First Schema Filtering for Small Context Models
- Source: https://github.com/Doorman11991/smallcode, commit 0722346
- Why NEXUS cares: SmallCode routes tool calls in two stages: first classifies the action type (query vs. mutate), then loads only the relevant tool schemas for that category. This reduces schema context by ~50% for models with ≤16k context. NEXUS's `src/nexus_os/mcp/functiongemma_router.py` is an intent classifier for function calling; the 2-stage pattern applied there would reduce schema load on the classifier and improve routing accuracy for constrained local models. The parallel executor introduced in v0.9.9 (Promise.all for independent plan steps) is also relevant to `src/nexus_os/engine/` DAG execution for concurrent task lanes.
- Suggested follow-up: Explore whether FunctionGemma Router can adopt a category-first pre-classification step before full tool schema dispatch — maps to the read-only (query) vs. write (mutate) split in smallcode.
