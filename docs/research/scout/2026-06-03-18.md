## Findings (NEXUS-relevant only)

### 1. SSRF in DesktopCommanderMCP — CVE-2026-10690
- Source: https://radar.offseq.com/threat/cve-2026-10690-server-side-request-forgery-in-wond-066cfa46
- Why NEXUS cares: CVSS 5.3 SSRF in `wonderwhy-er/DesktopCommanderMCP 0.2.37` — the `readFileFromUrl` function in `src/tools/filesystem.ts` lacks URL validation, allowing an attacker to induce the server into making arbitrary HTTP requests. This is the third distinct MCP SSRF in 72 hours (after CloudSEK's general analysis and the blender-mcp CVE), suggesting SSRF is a systematic class bug in MCP implementations. NEXUS's `src/nexus_os/security/sanitizer.py` (outbound tool-call filtering) and `src/nexus_os/mcp/server.py` (transport-layer validation) should explicitly block requests to RFC-1918, link-local, and metadata IPs as a baseline defense.
- Suggested follow-up: Add IMDS/IP range blocklist to `src/nexus_os/security/sanitizer.py` — specifically block `169.254.0.0/16` (AWS/Azure/GCP metadata) and other RFC-1918 ranges on all outbound tool-call HTTP requests.

### 2. SSRF in blender-mcp — CVE-2026-10662
- Source: https://radar.offseq.com/threat/cve-2026-10662-server-side-request-forgery-in-ahuj-9d47f91b
- Why NEXUS cares: Separate SSRF in `ahujasid/blender-mcp`'s ZIP File Handler — improper validation of `zip_file_url` in `src/blender_mcp/server.py`'s `requests.get` call enables arbitrary outbound HTTP requests from the server. Patch exists at commit `5b37be25`. Two SSRF CVEs in two different MCP servers in the same 24h window reinforces that NEXUS's MCP server implementation must treat all outbound HTTP as untrusted by default.
- Suggested follow-up: Audit `src/nexus_os/mcp/server.py` for any `requests.get` or `fetch` calls on user-controlled URLs — add strict URL allowlisting for any tool that triggers outbound HTTP.

### 3. MCPJam Inspector Unauthenticated RCE — CVE-2026-23744
- Source: https://github.com/jf-gondim/mcp-pwn
- Why NEXUS cares: Critical RCE (CVSS 9.8) in `MCPJam Inspector <= 1.4.2` — the `/api/mcp/connect` endpoint accepts unauthenticated JSON with `command` and `args` passed directly to Node.js `spawn`, enabling OS command injection and reverse shell as the process owner (often root). Patched in `>= 1.4.3`. This is a direct real-world example of the "unauthenticated MCP endpoint → full host compromise" attack chain that NEXUS's `src/nexus_os/security/sanitizer.py` and `src/nexus_os/governor/kaiju_auth.py` are designed to prevent. The MCPJam case is the most severe publicly documented MCP RCE since the Flowise stdio RCE (CVE-2026-40933) covered in the prior scout note.
- Suggested follow-up: Add endpoint authentication enforcement to `src/nexus_os/mcp/server.py` — all `/api/` routes should require bearer token auth by default, with explicit allowlist exemptions documented and reviewed.

### 4. OpenClaude MCP OAuth CSRF State Bypass — CVE-2026-42073
- Source: https://cve.imfht.com/intel/634952
- Why NEXUS cares: The OAuth callback handler in OpenClaude MCP validates CSRF state only when the `error` parameter is absent — if `error` is present, state validation is skipped entirely. An attacker can trigger `callback?error=triggered` to shut down the server without authentication. Root fix decouples state validation from other parameters. This class of auth-state bypass via error-parameter interference maps onto NEXUS's broader OAuth callback handling in `src/nexus_os/mcp/server.py` and the token validation in `src/nexus_os/governor/trust_kernel.py`.
- Suggested follow-up: Audit all OAuth callback handlers in `src/nexus_os/mcp/server.py` — ensure CSRF state is validated regardless of what other query parameters are present, and error conditions cannot disable security checks.

### 5. Manifest Network MCP — SSRF-Guarded Fetch Architecture
- Source: https://github.com/manifest-network/manifest-mcp-mono/commit/555cf32dafaadd07e1df9d055620233af350af04
- Why NEXUS cares: The `manifest-mcp-mono` project (fred component) now routes all HTTP provider calls through a shared SSRF guard: DNS-resolve + `ipaddr.js` range default-deny at connect time. The guard is exposed as `MANIFEST_FRED_FETCH_GUARDED` (default ON) and covers 11 Fred MCP tools (browse_catalog, deploy_app, app_status, etc.). This is the most concrete implementation pattern found for outbound HTTP hardening in MCP servers — it prevents DNS rebinding and credential leakage (Bearer tokens) via URL redirection. NEXUS's `src/nexus_os/security/sanitizer.py` should adopt a similar default-deny HTTP guard for all outbound tool calls.
- Suggested follow-up: Review `src/nexus_os/security/sanitizer.py` for an equivalent default-deny HTTP fetch guard — DNS resolution + range checking before connection, covering all outbound HTTP from tool calls.
