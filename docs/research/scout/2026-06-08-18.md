The attack chain: (1) victim receives a phishing email with a fake coding-task pretext (full-stack role, agent-leading developer role, code-review task, ERC-4626 Foundry test, AI payment agent project), (2) the email links to a GitHub or GitLab repo dressed as a coding assignment, (3) the victim clones the repo and opens it in VS Code or Cursor, (4) the repo contains a hidden `tasks.json` that *auto-executes on project-load* (VS Code prompts for trust, Cursor may run silently), (5) the tasks.json `command` spawns the Go-based Overlord-framework RAT on Linux/macOS, or a JavaScript loader inside the editor process on Windows (no disk footprint). The persistence model is a malicious VS Code extension that imitates a Google service and relaunches on editor reopen. Three concrete NEXUS maps. **(a) The editor-task-runner-as-execution-primitive sub-class ↔ NEXUS's `src/nexus_os/security/owasp_llm_patterns.json` (per 2026-06-08-00 #1)** — the existing pattern table has a Miasma Phase 2 entry that covers the *agent-reading-AGENTS.md* sub-class, but the new sub-class is *editor-running-tasks.json*. Add a `tasks_json_auto_execute` class signature: `(editor_kind matches vscode|cursor|windsur|cody|continue) AND (project_file matches .vscode/tasks.json OR .cursor/rules/*.mdc) AND (tasks_json_command_target matches network_sink|credential_store|shell_exec) AND (trust_prompt not_acknowledged OR editor_silent_run=true)`. The signature is class-shaped, so a future Cursor-only or Windsurf-only CVE that uses the same `tasks.json`-on-open primitive is caught by the same entry. **(b) The `editor-as-attack-surface` (not agent-as-attack-surface) framing ↔ NEXUS's `src/nexus_os/security/sanitizer.py` `ConfigFileWatchdog` from 2026-06-05-12 / 2026-06-07-18** — the existing watchdog snapshots IDE config files but does not *intervene* when the editor tries to execute a `tasks.json` command. A NEXUS-equipped VS Code / Cursor extension should hook the editor's task-runner API and refuse to run any `tasks.json` `command` that targets a network sink or a credential store, routing the request to a human-reviewer queue (mirroring the `NexusA2AChainGovernance` pattern from 2026-06-08-12 #2). **(c) The `editor-process` as the in-memory payload host ↔ NEXUS's `src/nexus_os/monitoring/token_policy.py` and `token_guard.py` from 2026-06-08-00 #1** — UNK_DeadDrop's Windows payload is a JavaScript loader *inside the editor process* (no disk footprint, so the existing `ConfigFileWatchdog` baseline-snapshot pattern doesn't catch it). NEXUS should add a per-process token-consumption guard that detects when an editor process (VS Code = `Code.exe` / `code`, Cursor = `Cursor.exe` / `cursor`, Windsurf = `Windsurf.exe` / `windsurf`) issues an unusually high number of outbound HTTP requests or filesystem reads in a short window, and emits a `nexus.editor.suspicious_io{editor, pid, http_count, fs_read_count, window_seconds, severity}` Loki event. The token-consumption guard pairs with the existing `TokenGuard` runtime token tracking + hard stops pattern (per the 2026-05-18 safety consolidation) to provide a per-process behavioral baseline.
