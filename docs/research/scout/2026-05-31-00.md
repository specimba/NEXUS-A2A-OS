## Findings (NEXUS-relevant only)

### 1. CVE-2026-40933 — Flowise MCP Command Injection via Unsafe stdio Serialization
- Source: https://www.securityweek.com/exploit-code-published-for-critical-flowise-rce-vulnerability/
- Why NEXUS cares: NIST advisory describes an unsafe serialization of stdio commands in the Anthropic MCP adapter — a malicious MCP Custom Tool configuration can inject arbitrary commands and achieve RCE on the underlying OS. NEXUS's `src/nexus_os/mcp/server.py` (NexusGovernanceMCP) runs MCP tool dispatch; the same systemic stdio serialization pattern is a direct attack surface. The Flowise community has proposed a pre-execution trust verification hook (`mcpTrustVerifier`) as mitigation — pluggable middleware that runs before any MCP tool dispatch, verifying server URI, tool name, and params against a user-implemented policy. NEXUS should adopt an equivalent guard: trust score on the MCP server identity + schema validation before dispatch, feeding into `src/nexus_os/governor/trust_kernel.py` as a CDR-stage gate.
- Suggested follow-up: Add a pre-execution trust hook to NexusGovernanceMCP that mirrors the proposed `mcpTrustVerifier` — verify serverUri + toolName before stdio dispatch, emit `mcp-server-trust-check` to the audit pipeline.

### 2. OmniRoute Adaptive Circuit Breaker v2 — Separate DEGRADED State + Per-Failure-Kind Thresholds
- Source: https://github.com/diegosouzapw/OmniRoute/pull/2671
- Why NEXUS cares: The PR introduces a DEGRADED state to the classic Closed/Open/Half-Open circuit breaker, plus per-failure-kind thresholds (429 vs. 5xx vs. quota-exhausted treated separately) and adaptive exponential backoff with automatic HALF-OPEN probing. This is architecturally distinct from the resilient-llm-router's per-failure-type cooldown already covered in the prior scan: DEGRADED state allows the breaker to shed load gracefully before fully opening, reducing retry storms on partially degraded providers. NEXUS's ModelRelay (`localhost:8040`) has no circuit breaker at all. Adding a 3-state-per-failure-class breaker here would prevent a single rate-limited API key from triggering retry storms that also exhaust quota — a scenario that compounds latency under load.
- Suggested follow-up: Prototype a 4-state (Closed / DEGRADED / Open / Half-Open) circuit breaker in `src/nexus_os/relay/` with per-HTTP-status thresholds; wire `fail-open` for read-only queries, `fail-closed` for writes.

### 3. ToolOutputGuardrail — Indirect Prompt Injection via MCP Tool Results
- Source: https://github.com/ruvnet/ruflo/commit/3de265e76e2d3bdec87f907e37995c7f361335c2
- Why NEXUS cares: The commit proposes a `ToolOutputGuardrail` that intercepts all MCP tool results, memory retrievals, and external API responses before they enter agent reasoning — addressing a critical gap where current defenses do not screen semantic content returned by tools. The guardrail runs in parallel (no added latency to the critical path) and emits `tool-output-injection-detected` security events to the audit pipeline. This is a concrete implementation of the OWASP ASI01 category (indirect prompt injection). NEXUS's `src/nexus_os/security/sanitizer.py` handles prompt injection on terminal output but does not currently screen incoming tool-output content before it enters agent context. Adding this layer would close the loop on the full injection surface.
- Suggested follow-up: Implement a parallel `ToolOutputGuardrail` in the MCP tool result handler — scan returned content for injection markers (system-reminder patterns, hidden instructions) before appending to agent context; emit security events to `src/nexus_os/observability/audit_log.py`.
